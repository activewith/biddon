# 입찰적격도구 회귀 테스트

`index.html`은 수정하지 않습니다. jsdom으로 앱을 불러와 계산 함수만 호출해 결과를 검사합니다.
네트워크(동기화)·팝업은 차단되므로 실제 데이터에 영향이 없습니다.

## 실행

```
cd tests
npm install      # 최초 1회
npm test
```

GitHub에 push하면 Actions(회귀 테스트)가 자동 실행되고, 실패하면 GitHub 알림이 옵니다.
※ 테스트 실패가 GitHub Pages 배포를 막지는 않습니다(알림 용도).

## 테스트 구분

| 파일 | 구분 | 내용 |
|---|---|---|
| 00-load | 기본 | 로드 오류 없음, 핵심 함수 존재 |
| 01-tables-snapshot | 기준표 스냅샷 | 적격UPDATE 대상 숫자표 전체 고정 — 숫자 하나라도 바뀌면 실패 |
| 02-econ-boundaries | 기준 | 경영상태 배점표 경계값(부채 "미만", 유동·영업 "이상"), 점수 역전 검출 |
| 03-module-consistency | 기준 | LH2=별표6·LH3=별표7A, 레지스트리 매핑, 구간 경계, 만점 15점 |
| 04-rail-lh | 기준 | 철도 100점제 구간·시공계획(50억↑만)·별표5 소방, 만점합 95, LH 가격점수 |
| 05-judge | 현재동작 | 조달청 판정 엔진 게이트·신용등급 구제 |
| 06-extract | 현재동작 | 공고문분석 — 과거 버그 문구 형태 |
| 13-auto-dist-partner-step | 현재동작 | 자동분배 — 우선협정업체 투입 시 지역 지분 5%단위 하향(지역의무지분까지) |

- **기준**: 기준서 해석에 근거한 검사. 실패 = 버그 가능성 높음.
- **현재동작**: 지금 코드의 결과를 고정. 실패 = 의도치 않은 변경 여부 확인 필요.

## 기준 개정 시

1. 적격UPDATE 숫자표 또는 코드 수정
2. `npm test` → `01-tables-snapshot`이 바뀐 표 이름을 알려줌
3. 의도한 개정이 맞으면 `npm run snapshot:update` 후 커밋 → git diff에 바뀐 숫자가 그대로 남음

## 실제 공고문 추가(권장)

`tests/fixtures/공고문/이름.txt`(공고문 붙여넣기 원문)와 `이름.expected.json`(정답 필드만)을 넣으면
자동으로 테스트에 포함됩니다.

```json
{ "공종": "전기", "추정가격": 1234567890, "적격기준": "지자체", "지역선택": ["대전"] }
```

※ 이 저장소는 공개(GitHub Pages)입니다. 업체 정보·내부 자료는 fixture에 넣지 마세요. 공고문은 공개 자료라 무방합니다.
